# Security Controls

The one list of the security measures in place, each with the test or the command that shows it
runs, or "none" where nothing does. Rebuilt by board row W82 on 2026-10-17, from `main` at `2f13e22` (ADR-0170). The evidence and
the gaps are in `docs/analysis/2026-10-17-w82-security-baseline.md`; the OWASP ASVS 5.0.0 Level 2
check, item by item, is in `docs/analysis/2026-10-17-asvs-5-level-2-check.md`.

**What keeps this list true.** `tests/unit/test_security_controls_cite_real_tests.py` fails when a
test named in a Proof cell is renamed, deleted or marked `@pytest.mark.skip`, when a measure's row
is removed, renumbered or moved out of the measure tables, or when a row claims `TESTED` or `PARTIAL` with no
test. It cannot tell whether a named
test really exercises its measure; review does that.

**How to read the tables.**
- **Proof** names pytest tests (`file::test`) that fail when the measure is removed, or a Playwright
  spec and its test title. `[B]` marks a test that drives the code (a request, a call, a
  subprocess); `[S]` marks one that only reads source or configuration text. "none" means no test
  was found that would fail without the measure.
- **The pytest lanes** are the `pytest (Python 3.12)` job in `.github/workflows/test.yml` and the
  `validate-and-test` job in `.github/workflows/ci.yml`. Both run every test under `tests/` on every
  pull request. The Playwright specs run in `e2e axe + parity (chromium)` (`.github/workflows/e2e.yml`)
  unless a row says otherwise.
- **Status:** `TESTED` (a named test fails without it), `PARTIAL` (the cell says what is missing),
  `CODE-ONLY` (the code does it and no test would catch its removal), `MEASURED` (the session read
  it from production or from GitHub), `UNKNOWN` (nothing here can settle it).
- **Where** gives `file:line` at commit `2f13e22`; lines move. A `.py`, `.js` or `.html` path
  without a folder, or one starting `static/` or `templates/`, is under `src/product_app/`; `Dockerfile`, `fly.toml`, `Makefile` and
  `.dockerignore` are at the root, and a `.yml` without a folder is under `.github/workflows/`.
- **Dates:** the session read production on 2026-10-16 between 20:35 and 21:00 UTC; GitHub's branch
  protection, Actions settings and repository secrets at 20:35 UTC that day; and GitHub's security
  and analysis settings, the production environment and the owner's account on 2026-10-17 between
  05:16 and 06:00 UTC (all 2026-10-17 in India).
- The rows were written by a read-only agent and checked by the session: every named test exists
  (the committed test checks this on every run), and the measured rows were read by the session
  itself. That a named test fails without its measure is the agent's judgement from reading the test;
  review checked it by mutation for SC-08, SC-22, SC-28, SC-31 and SC-46.
- "Row Wxx" points to the board row (`docs/65-open-work.md`) that closes the gap.

  their spend counted per network (ADR-0144). A browser session is required (SC-25), not an account.
  The old release blocker "any query execution path available to anonymous users" no longer applies.
- **CTRL-012, "secret scanning, dependency scanning, SAST, and redaction checks before release".**
  Taken one part at a time: the secret scan runs on every pull request (SC-82); the library audit runs
  on every pull request (SC-83); log and Sentry redaction are tested (SC-75, SC-76); no SAST tool

  turned on (row W92).
- **CTRL-005, "redact from … prompts … analytics".** No step redacts prompts: the key is simply never
  put into one, and no test checks that (SC-77). There is no analytics code.
- **CTRL-008, warnings before execution.** In place (SC-68). The page gap of row W100 was fixed by W100 (ADR-0173).
- **CTRL-011, "preserve disagreement, uncertainty, provider failures".** Product behaviour, not a
  security measure, so it is not carried into this list.

## Release blockers

A change that does any of these is not merged:
- returns a provider key, or any server secret, to the browser;
- shows one account's runs, history or key to another account;
- logs or returns a raw credential on an error path;
- runs a high-stakes question without its warning. The page could do this until W100 fixed it (SC-68, ADR-0173).

## Measures no test would miss

- **Sign-in and sessions:** the absent cookie `Domain`; the startup refusals for an empty `QUORUM_TOKEN_SECRET`, an unset
