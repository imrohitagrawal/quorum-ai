# ADR-0033: `docs/factory/` drops its 8 duplicate-numbered files; `docs/` root is canonical

## Status

Accepted — 2026-08-11 (repo-housekeeping PR 3)

## Context

`scripts/validate_quality_contracts.py` explains why `docs/factory/` exists:
this repo was bootstrapped from a Codex Product Factory template, and
`docs/factory/` is where the factory's own bootstrap process copies its meta
docs. Most of `docs/factory/`'s 31 files (23 of them) have no counterpart at
`docs/` root — they document the factory process itself (skill contracts,
quality-gate contracts, MCP integration model) and are the only copy.

Eight numbers collide with `docs/` root: `38`, `39`, `105`, `106`, `107`,
`108`, `109`, `110`. Verified by `md5`:

```
$ for n in 105 106 107 108 110 39 109 38; do
    md5 "docs/factory/${n}-*.md" "docs/${n}-*.md"
  done
```

Six are byte-identical (`105`, `106`, `107`, `108`, `110`, `39`) — plain
duplication, no decision needed. Two have **diverged** — same number, real
content difference, and this is the decision this ADR records.

### `109-contract-and-schema-governance.md`

`git log` shows `docs/factory/109` last touched at the initial commit
(`d3bbec2`); `docs/109` was extended by a later commit
(`09f9707`, "Fix OpenAPI contract drift and make it self-enforcing (#10)").
`diff` confirms `docs/` root is a strict superset — it has 11 more lines: a
`make openapi-check` reference and a full `## openapi.yaml is generated and
guarded` section describing the drift-guard this repo actually built. The
factory copy is a stale pre-feature snapshot.

### `38-atlassian-integration-roadmap.md`

Both trace to the same initial commit — no later edit differentiates them,
so this is a content fork from day one, not staleness. `docs/` root (112
lines) is substantially more developed than `docs/factory/` (52 lines): it
adds a "Systems Of Record" table, per-phase metadata requirements (Jira
delivery-item fields, Confluence page fields), a longer roadblocks/controls
table, and split exit criteria for manual-draft vs. assisted-publication
phases. The factory copy reads as an earlier, less-specified draft of the
same roadmap; the root copy is what this project's Jira/Confluence workflow
actually documents elsewhere (`docs/34-jira-issue-authoring.md`,
`docs/35-confluence-operational-guide.md`,
`docs/37-jira-confluence-sync-log.md` — all cited by the root version, none
cited by the factory version).

## Decision

**`docs/` root is canonical for all 8 colliding numbers. `docs/factory/`'s
copies are deleted** (git-recoverable — `git show <pre-PR3-sha>:docs/factory/<file>`
retrieves any of them forever). This applies uniformly, not just to the 2
diverged pairs: even where content was identical, root is documented as the
project's numbered-doc series (`docs/17-requirement-registry.md`,
`docs/18-requirement-traceability-matrix.md`, and the whole `docs/NN-*.md`
convention this repo actually follows) and `docs/factory/` is documented as a
bootstrap artifact, not a second source of truth.

`scripts/validate_quality_contracts.py`'s required list only names 4 files
under `docs/factory/` (`12`, `14`, `15`, `16` — none of the 8 colliding
numbers), and its own fallback logic already tolerates a file existing at
either `docs/factory/<name>` or `docs/<name>` — so this decision needs no
gate change.

### Rejected alternative: keep `docs/factory/` as canonical, delete root

Rejected because the root copies are the ones with the newer/more complete
content (109, and arguably 38), and because every other cross-reference in
the repo (ADRs, `docs/17-*`, `docs/18-*`) points at `docs/NN-*.md`, not
`docs/factory/NN-*.md`. Flipping canonicity would have made the more-current
content unreachable from its usual location.

### Rejected alternative: keep both, do nothing

Rejected — this is exactly the "documented nowhere, so it silently
diverges again" failure mode PR 6 (numbering-scheme ADR + gate) exists to
close. Two copies of the same numbered doc invites exactly the kind of
drift `109` and `38` already show.

## Consequences

- `docs/factory/` now holds only the 23 files with no root counterpart —
  purely factory-process documentation, no longer a partial mirror.
- Anyone who edited `docs/factory/109` or `docs/factory/38` expecting it to
  be read must now edit `docs/109-contract-and-schema-governance.md` /
  `docs/38-atlassian-integration-roadmap.md` instead.
- If `docs/factory/`'s content is regenerated by a future factory bootstrap
  run, a fresh collision could reintroduce this exact problem — the fix here
  is a one-time cleanup, not a standing guard. (A standing guard against new
  `docs/` number collisions is PR 6's scope, not this one's — it would not by
  itself catch a `docs/factory/`-vs-`docs/` divergence unless `docs/factory/`
  is included in its scan.)
