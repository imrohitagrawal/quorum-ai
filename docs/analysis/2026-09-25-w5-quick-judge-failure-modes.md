# W5, fourth pull request: how a verification-only judge with per-claim evidence can fail

Written before the code (AGENTS.md rule 16e). The owner decided on
2026-09-24 that a quick answer shows *"Judge: well supported/partly
supported/not supported along with reasons and artifacts to support why"*,
and that the judge does *"verification only"*
(`docs/analysis/2026-09-24-w5-parked.md`). Reading "artifacts to support
why" as per-claim evidence (a quote from the answer, the source it cites,
and whether that source supports it) is the session's reading; the owner has
not confirmed it. ADR-0127 and its failure-modes page
(`docs/analysis/2026-09-25-w5-quick-verdict-failure-modes.md`) hold the rows
this pull request inherits; this page lists what the new prompt and the new
claim list add.

| # | Failure | Harm | Design answer |
|---|---|---|---|
| 1 | **Injection through a claim.** A claim's `quote` is text the judge writes. A cited title or the answer itself can steer the judge into writing attacker text there: a link, a phone number, "ignore the notice above". | Attacker text on the page under the product's "Judge" heading; decision D-5 (no judge-written text is served) broken. | A claim is served only if its quote, reduced to the text a reader sees (Markdown rendered to plain text, whitespace collapsed), is part of the answer's own displayed text, block by block, on word boundaries, and part of the answer's raw text with only its emphasis and code markers removed. So the judge can choose which part of the answer to show; it cannot author one. A sentinel written by the judge and not in the answer is pinned to reach no response. |
| 2 | **Markup in a quote.** A quote carrying `<script>`, `<img onerror>` or Markdown that would become a link. | Script or a live link on the page. | The server serves plain text only (the rendered text, no markup); the page writes it with `textContent`. A quote that looks like HTML and IS in the answer is served as that text, and the answer itself already shows it as text (`html: false` in both renderers). |
| 3 | **Huge output.** Hundreds of claims, or a quote of 50,000 characters. | A response that fails to build, or a page flooded with text. | The strict schema allows at most 8 claims and 300 characters a quote; a verdict breaking either is non-conforming, like any other schema breach, and reads `not_checked`. The serving filter re-applies both caps on its own, so the served list is bounded even for a verdict the schema did not produce. |
| 4 | **A malformed verdict fails the response.** Round 2 of #507's review found a served field that could exceed its own limit and fail the whole response (which also skipped the run's billing correction). | A 500 on a finished run and a missing ledger correction. | The served claim model has no limit that the filter does not enforce first; the filter never raises on any string or integer; a claim that fails a rule is dropped and counted in `claims_dropped`, never raised. Pinned with a hostile verdict built past the schema. |
| 5 | **A claim that points nowhere.** `source` 0, negative, or past the end of the sources the judge was shown; "unsourced" with a source number; "supported" with none. | "Supported by source 7" when there is no source 7, or a support word with no source behind it. | `source` must be null or 1..N of `sources_checked`, which is the same list, in the same order, that numbers the prompt's SOURCES block (`judge_evidence_sources`). "unsourced" requires a null source and the other two require one. Anything else is dropped and counted. |
| 6 | **The judge answers instead of verifying.** It writes its own answer, adds facts, or grades against its own knowledge. | The owner's "verification only" is not what runs; a second opinion is shown as a check. | A separate system prompt says to check the one answer against its listed sources and not to answer the question or add knowledge; the schema has no field for an answer; a quote the judge wrote itself fails the substring rule. What the scores reflect is still the judge's reading and cannot be proved here: the prompt's quality on real answers is UNMEASURED (no live window, no paid call). |
| 7 | **The judge cannot see the pages.** Its SOURCES block holds each page's title and address only (ADR-0124's page fetcher ships off). | "Supported" read as "the page was checked". | The page says so under the claim list: the judge saw each source's title and address, not the page. The prompt says so too and asks the judge to judge support from what is shown, not from memory. When #447's wiring hands the judge page text, that sentence must change with it. |
| 8 | **Cost.** The claim list makes the judge's answer longer. | A dearer judge call; an estimate that under-states it. | No money value moves (`quorum_eval_judge_max_tokens` 1024, `cost_judge_output_tokens` 150, `cost_judge_input_tokens` 7300, the bound's judge reserve). The bound prices the output at the 1024 cap, so it covers any quick judge answer. The point estimate's 150 output tokens was measured on the panel judge and may under-state the quick one: UNMEASURED. The bound's input reserve for a quick run still includes five synthesis sections a quick run never sends (15,000 tokens), which covers the longer quick system prompt; pinned by a test. |
| 9 | **The cap truncates the answer.** A reasoning model spends part of the 1024 tokens thinking; 8 claims of 300 characters is about 600 more. | A truncated JSON answer: billed, and no verdict. | It reads `not_checked` (never a level the judge did not give) and is billed as a dispatched call, as today. How often it happens is UNMEASURED. |
| 10 | **Panel regression.** The panel judge's prompt, id, schema or parse changes. | Every panel run's judge changes without the paid golden re-capture a prompt change needs. | The panel prompt, `JUDGE_PROMPT_ID`, `EvalJudgeVerdict` and `parse_judge_verdict` are untouched. The prompt's bytes are pinned by a hash, and a before/after dump of the panel prompt, parse results and provider-call arguments is compared. |
| 11 | **`disagreement_preserved` at one model.** The field asks whether model disagreement survived into the synthesis; a quick answer has one model and no synthesis. | A meaningless yes/no that some reader later treats as a finding. | Not asked and not accepted: the quick schema has no such field (a response carrying it is non-conforming), and the quick verdict never enters the panel evaluation engine, whose record needs it. |
| 12 | **Billing or memo drift.** The quick verdict is memoised or billed differently from the panel's. | A judge dollar missing from the ledger, or a second paid call. | Same memo, same service, same provider seam, same usage and status capture; only the prompt and the parser differ. The ledger test runs in both modes and now also checks the quick verdict parsed. |
| 13 | **A trivial or misleading fragment.** The judge quotes one common word ("the"), or a fragment that drops a negation ("vaccines cause autism" out of "It is false that vaccines cause autism"), and labels it. | A misleading line, though it is text already on the page. | Narrowed, not closed: a quote must start and end on word boundaries (a cut inside a word is dropped), but a whole-word fragment is served; no minimum length or sentence rule is set, because any number would be a guess. The label is the judge's, as a whole-sentence label would be. Recorded as a known limit. |
| 14 | **The rationale leaks through the new path.** | D-5 broken. | Still never served. The sentinel test is extended to a sentinel inside a claim. |
